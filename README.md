# Zera3ty AI

منصة عربية RTL لاستقبال صور النباتات ومتابعة الحالات والتواصل مع فريق زراعتي. التطبيق مبني بـ Next.js 15 وReact 19 وTailwind CSS 3 وSupabase.

## المعمارية

اخترنا **Supabase PostgreSQL** بدل MySQL لهذه النسخة. Supabase Auth وStorage وRealtime مبنية حول PostgreSQL؛ إضافة MySQL كانت ستخلق مصدرين للبيانات وهوية مكررة وتزامنًا يحتاج إلى خدمة إضافية. PostgreSQL هو المصدر الوحيد للحسابات والاشتراكات والحالات والردود، وRealtime يستمع لتغييرات `submissions` و`replies` مع تطبيق RLS.

- **Auth:** Supabase Auth بالبريد وكلمة المرور. التسجيل يدخل المستخدم مباشرة دون رسالة تأكيد عند إيقاف **Confirm email** في إعدادات Supabase.
- **البيانات والصلاحيات:** PostgreSQL وRLS؛ كل مستخدم يرى ملفه واشتراكه وصوره وردوده فقط.
- **الصور:** Bucket خاص `plant-submissions`. يمر الرفع عبر Route خادمي يتحقق من الحجم وبصمة JPG/PNG/WEBP ثم يرفع بجلسة المستخدم؛ سياسة Storage تسمح لكل مستخدم بمجلده فقط، وروابط العرض مؤقتة وموقعة.
- **الإدارة:** الدور `profiles.role` يتحقق منه الخادم في كل صفحة إدارة وAPI؛ لا يمكن للمستخدم ترقية نفسه. لا توجد Service Role Key في المتصفح.
- **البريد:** لا يعتمد التطبيق على خدمة بريد خارجية. تظهر ردود الإدارة للمستخدم داخل حسابه، وتصل التحديثات لحظيًا عند تفعيل Realtime.

## التشغيل محليًا

1. ثبّت Node.js 20.9 أو أحدث.
2. انسخ `.env.example` إلى `.env.local` وأدخل عنوان مشروع Supabase والمفتاح العام `publishable` (أو `anon` القديم) في المتغير `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
3. نفّذ `supabase/schema.sql` في SQL Editor داخل مشروع Supabase.
4. في Supabase Auth، فعّل Email provider، أوقف **Confirm email**، وأضف `http://localhost:3000/auth/callback` إلى Redirect URLs.
5. نفّذ `npm install` ثم `npm run dev` وافتح `http://localhost:3000`.

إذا لم تُضبط Supabase، يمكن تصفح الصفحة التعريفية لكن التسجيل والرفع والعدادات وبيانات الإدارة تحتاج الاتصال الفعلي.

## إعداد Admin

1. استخدم حسابًا موجودًا، أو أضف مستخدمًا إداريًا من Supabase Authentication → Users بصلاحية مالك المشروع.
2. بعد تشغيل `schema.sql`، افتح SQL Editor بصلاحية مالك المشروع ونفّذ:

```sql
update public.profiles
set role = 'admin'
where email = 'admin@example.com';
```

3. سجّل خروجًا ثم دخولًا. ستظهر لوحة الإدارة للحساب الإداري فقط. لا تمنح حسابات غير موثوقة هذا الدور.

## النشر

المستودع موجود على GitHub على الفرع `codex/zera3ty-ai-mvp` ومربوط بمشروع Vercel. يتطلب تشغيل الإنتاج إعداد `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` في بيئات Vercel ثم نشرًا جديدًا. أضف عنوان الإنتاج إلى Supabase Auth Site URL وRedirect URLs، مثل `https://zera3ty-ai.vercel.app/auth/callback`.

## الوظائف الحالية

- صفحة تعريف عربية RTL متجاوبة مع إحصاءات حية من دالة قاعدة البيانات العامة.
- إنشاء حساب والدخول فورًا دون رسالة تأكيد، واستعادة كلمة المرور (تتطلب البريد)، وتعديل الاسم والخروج.
- اشتراك واحد لكل حساب، بقيد `UNIQUE(user_id)`.
- رفع صور خاصة مع معاينة وفحص الحجم ونوع المحتوى الفعلي.
- حساب مستخدم لعرض الصور والحالات والردود وتحديثها لحظيًا عند تفعيل Realtime.
- لوحة إدارة للمؤشرات والمستخدمين والطلبات ورسائل التواصل وتغيير الحالة وإرسال الردود داخل حساب المستخدم.
- سياسة خصوصية أولية وصفحات 404/500.

## ما يحتاج إعدادًا أو مراجعة قبل الإطلاق

- إنشاء وربط مشروع Supabase ومشروع Vercel وإضافة متغيرات البيئة.
- ترقية أول مسؤول يدويًا، وضبط روابط Auth والنطاق النهائي.
- تعطيل **Confirm email** في Supabase Auth حتى يعمل التسجيل دون رسالة تأكيد.
- Rate limit رسائل التواصل الحالي داخل الذاكرة؛ في Vercel يحتاج إلى خدمة مشتركة مثل Upstash أو بوابة حماية قبل حملة عامة.
- الذكاء الاصطناعي لتحليل الأمراض غير موصول بعد؛ النسخة الحالية تستقبل الحالات ويراجعها الفريق يدويًا.
- سياسة الخصوصية نص MVP وتحتاج مراجعة قانونية، كما ينبغي تحديد سياسة حذف البيانات والاحتفاظ بها قبل جمع بيانات حقيقية.
