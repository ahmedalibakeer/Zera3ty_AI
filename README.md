# Zera3ty AI

منصة عربية RTL لاستقبال صور النباتات ومتابعة الحالات والتواصل مع فريق زراعتي. التطبيق مبني بـ Next.js 15 وReact 19 وTailwind CSS 3 وSupabase.

## المعمارية

اخترنا **Supabase PostgreSQL** بدل MySQL لهذه النسخة. Supabase Auth وStorage وRealtime مبنية حول PostgreSQL؛ إضافة MySQL كانت ستخلق مصدرين للبيانات وهوية مكررة وتزامنًا يحتاج إلى خدمة إضافية. PostgreSQL هو المصدر الوحيد للحسابات والاشتراكات والحالات والردود، وRealtime يستمع لتغييرات `submissions` و`replies` مع تطبيق RLS.

- **Auth:** Supabase Auth بالبريد وكلمة المرور، مع تأكيد البريد واستعادة كلمة المرور.
- **البيانات والصلاحيات:** PostgreSQL وRLS؛ كل مستخدم يرى ملفه واشتراكه وصوره وردوده فقط.
- **الصور:** Bucket خاص `plant-submissions`. يمر الرفع عبر Route خادمي يتحقق من الحجم وبصمة JPG/PNG/WEBP ثم يرفع بخدمة Storage إدارية server-only؛ صلاحية الرفع غير متاحة للمتصفح. روابط العرض مؤقتة وموقعة.
- **الإدارة:** الدور `profiles.role` يتحقق منه الخادم في كل صفحة إدارة وAPI؛ لا يمكن للمستخدم ترقية نفسه. لا توجد Service Role Key في المتصفح.
- **البريد:** Resend اختياري. يسجل النظام حالة الإرسال لكل رد ويستخدم مفتاح idempotency لمنع إنشاء الرد نفسه مرتين عند إعادة الطلب.

## التشغيل محليًا

1. ثبّت Node.js 20.9 أو أحدث.
2. انسخ `.env.example` إلى `.env.local` وأدخل عنوان مشروع Supabase ومفتاح `anon` العام ومفتاح `service_role` في الخادم فقط. لا تضع `SUPABASE_SERVICE_ROLE_KEY` في إعدادات `NEXT_PUBLIC_*` أو داخل المتصفح.
3. نفّذ `supabase/schema.sql` في SQL Editor داخل مشروع Supabase.
4. في Supabase Auth، فعّل Email provider وأضف `http://localhost:3000/auth/callback` إلى Redirect URLs.
5. نفّذ `npm install` ثم `npm run dev` وافتح `http://localhost:3000`.

إذا لم تُضبط Supabase، يمكن تصفح الصفحة التعريفية لكن التسجيل والرفع والعدادات وبيانات الإدارة تحتاج الاتصال الفعلي.

## إعداد Admin

1. أنشئ حسابًا عاديًا من الموقع وأكّد البريد الإلكتروني.
2. بعد تشغيل `schema.sql`، افتح SQL Editor بصلاحية مالك المشروع ونفّذ:

```sql
update public.profiles
set role = 'admin'
where email = 'admin@example.com';
```

3. سجّل خروجًا ثم دخولًا. ستظهر لوحة الإدارة للحساب الإداري فقط. لا تمنح حسابات غير موثوقة هذا الدور.

## إعداد البريد عبر Resend

أضف `RESEND_API_KEY` و`RESEND_FROM_EMAIL` إلى متغيرات الخادم، وتحقق من نطاق المرسل في Resend. دون هذه المتغيرات، تحفظ الردود داخل الموقع ولا يرسل النظام البريد. اختبار التسليم الفعلي يتطلب API Key ونطاقًا موثقًا.

## النشر

المستودع موجود على GitHub على الفرع `codex/zera3ty-ai-mvp`. أنشئ مشروعًا في Vercel واربط هذا المستودع والفرع، ثم أضف المتغيرات الموجودة في `.env.example` إلى إعدادات Production وPreview. أضف عنوان النشر إلى Supabase Auth Site URL وRedirect URLs، مثل `https://zera3ty-ai.vercel.app/auth/callback`. شغّل Production Build من إعدادات Vercel.

الموقع لم يُنشر بعد ولم يُربط بمشروع Supabase/Vercel، لذلك لا يوجد رابط تشغيل عام أو اختبار تكامل حي حتى الآن. يلزم إعداد المشاريع الخارجية ومتغيرات البيئة قبل تفعيل ذلك. خطة Supabase المجانية لها حدود استخدام وتوفر؛ تحقق من حدود الخطة الحالية قبل الإطلاق التجاري.

## الوظائف الحالية

- صفحة تعريف عربية RTL متجاوبة مع إحصاءات حية من دالة قاعدة البيانات العامة.
- التسجيل والدخول وتأكيد البريد واستعادة كلمة المرور وتعديل الاسم والخروج.
- اشتراك واحد لكل حساب، بقيد `UNIQUE(user_id)`.
- رفع صور خاصة مع معاينة وفحص الحجم ونوع المحتوى الفعلي.
- حساب مستخدم لعرض الصور والحالات والردود وتحديثها لحظيًا عند تفعيل Realtime.
- لوحة إدارة للمؤشرات والمستخدمين والطلبات ورسائل التواصل وتغيير الحالة وإرسال الردود.
- بريد Resend اختياري، وسياسة خصوصية أولية وصفحات 404/500.

## ما يحتاج إعدادًا أو مراجعة قبل الإطلاق

- إنشاء وربط مشروع Supabase ومشروع Vercel وإضافة متغيرات البيئة.
- ترقية أول مسؤول يدويًا، وضبط روابط Auth والنطاق النهائي.
- إعداد Resend والتحقق من النطاق لاختبار البريد.
- Rate limit رسائل التواصل الحالي داخل الذاكرة؛ في Vercel يحتاج إلى خدمة مشتركة مثل Upstash أو بوابة حماية قبل حملة عامة.
- الذكاء الاصطناعي لتحليل الأمراض غير موصول بعد؛ النسخة الحالية تستقبل الحالات ويراجعها الفريق يدويًا.
- سياسة الخصوصية نص MVP وتحتاج مراجعة قانونية، كما ينبغي تحديد سياسة حذف البيانات والاحتفاظ بها قبل جمع بيانات حقيقية.
